# 技术适配声明

## 1. 产品形态判断
- 产品类型与核心任务：给电商美工和短剧创作者用的本地网页工作台。一条工作流做商品主图、场景图、批量尺寸和风格、多 SKU 一致；另一条做分镜、出图、出视频、角色一致、批量导出。
- 核心交互：分阶段确认。用户用自己的话写要求，DeepSeek 看着参考图收成生成卡，用户确认一次，再排队生图或生视频。
- 开发路径：纵向切片。画布本身就是产品，不能先只做接口、最后再补一块画布。
- 验收界面：纵向切片界面。2-1 起就是一块可平移、缩放、放节点的画布，从它出现起按正式界面验收。阶段 3 不另起一套页面，也不把这块画布废弃。整仓 infinite-canvas 这一段不接入，原因见第 4 节。
- 上线套餐：不启用。台账 D9 已定，这次只在本机跑通，不部署。
- 当前阶段范围：只写这份声明和路线图，不写代码。下一段只做路线图里的 2-1。

## 2. 采用的默认方案
- Python 3.12：本机有 Python 3.12.15。业务、排队、三家接口放在后端，和画布页面分开。
- FastAPI：把「写生成卡、确认、生图、生视频、查进度」做成可测试的接口。
- Pydantic：生成卡、任务状态、接口报错都做结构校验。模型没按字段返回就当失败，不把半截文字当成成功。
- pytest：每个子阶段用假的模型响应检查排队、确认、失败和重启恢复。真模型另做冒烟，假响应不算验收通过。
- Git：工具包已经是仓库。密钥文件继续忽略。
- 官方或兼容接口：DeepSeek、商汤、蚂蚁都由后端调用。页面不保存钥匙。
- 邀请码登录：第一张业务表就带「这是谁的」。一个人只能看到自己的作品。
- 图片和视频放在产品文件夹的本地目录，不塞进数据库。目录已在忽略清单里。
- 慢任务用「提交后拿任务号，再查进度」。不做流式输出。用户要看的是画布上的成图，不是一个字一个字的过程。

## 3. 触发的按需模块
- SQLite：有用户、作品、商品、镜头、角色卡、任务，还要按人隔离。2-1 就建库。不用向量库，没有文档检索。
- 任务记录：生图和生视频都可能超过一次请求的时间，关掉再打开还要能接着查。2-1 就把任务存进数据库。先不另装一套任务队列软件，因为商汤全局只允许一个请求，蚂蚁视频一次也只出一条。
- 本地文件目录：2-1 起保存上传图和生成结果。
- 图片裁切库：批量改尺寸不调模型，2-2 才引入。
- 不引入：知识库、Word、PDF、文字识别、定时任务、多 Agent、插件协议。需求没有这些。
- 没有 Agent 工坊的单独方案文件。原始需求里的开源清单已经在阶段 0 查过，结论记在台账 D13，不把十几个仓库都当成要接的模块。

固定流程由代码按顺序执行：看图写卡 → 等你确认 → 商汤出图 → 需要时蚂蚁出视频。模型不能自己决定再调下一次，也不能自己决定花钱。

## 4. 偏离或暂缓的默认方案
- 默认网页技术是 Next.js。替代：正式界面是一块无限画布（平移、缩放、节点）。原因：你指定先用开源 infinite-canvas。2-1 核对后没有整仓接入：那个项目用 bun 跑测试，没有本工具包要的检查脚本，出图也不经过「确认生成卡」和商汤排队。影响：这一段的画布由我们按同样的操作来做（拖动画布、缩放、看节点），后端按已定的 DeepSeek 和商汤来接。若后面发现自建画布撑不住两条工作流，再评估整仓接入。
- 默认可以先用单个 HTML 做临时验收页。替代：不做临时页。原因：画布会留在正式产品里。影响：2-1 就要在这块画布上点通一条电商路径。
- 默认上线到腾讯云。暂缓：这次不上线。原因：D9。影响：不做注册云、实名、公网地址。阶段 3 通过后直接收尾。
- 默认不把整套开源短剧软件搬进来。暂缓：Toonflow、Jellyfish、OpenStudio 只借鉴步骤。原因：它们的模型接口不是 DeepSeek、商汤、蚂蚁。影响：短剧和电商的步骤我们做，但不运行第二套软件。
- 本机锁脸仓库暂缓：PuLID、IP-Adapter、ComfyUI 不接入。原因：生图走商汤、视频走蚂蚁。影响：一致性靠锁定的生成卡和参考图，不靠本机模型。
- 独立任务队列暂缓。重新评估条件：一条视频经常超过 10 分钟，并且重启后不能按任务号续上。

## 5. 强制底线检查
- 密钥与隐私：待处理。钥匙只放在后端本地环境文件，不进页面、不进仓库、不进对话。日志不记钥匙和整张用户图。开发时可以先空着，验收前你再填。
- 数据与任务可恢复：待处理。2-1 起任务和作品进数据库，文件进本地目录，重启后还在。
- 输入输出校验：待处理。生成卡和接口都做结构校验。上传只收 jpg、png、webp，单张不超过 10 MB。
- 错误与日志边界：待处理。失败返回固定的错误格式，不把内部报错原样给页面。
- 测试与真实模型验收：每个子阶段先跑自动化测试，再各做一次真调用。没有真结果就不能说这一段完成。蚂蚁视频在免费额度不够时先报价，你同意才继续。

环境已看过：产品文件夹里还没有代码。Python 3.12.15 和 Node 都在。Git 仓库已在，密钥忽略规则有效。本机 3000 和 5173 端口没有被占用。

## 6. 需要产品经理决定的问题
- 无。阶段 0 台账里没有仍待定、且会挡住这一段的事项。生成好不好的数字标准仍是「待样例打分」，留到第一次真出图，不在这一段问。

## 7. 子阶段规划
- 依据：这次做完两条工作流和画布；视频可以在出图之后；不上线。开发路径是纵向切片，所以每一段都在画布上能点，而不是只交接口。
- 两段场景的关系：2-1 和 2-2 是场景 1（电商）。2-1 是基础功能，2-2 是在这条基础上做批量、多 SKU 和改尺寸。2-3 和 2-4 是场景 2（短剧）。短剧复用 2-1 的画布、生成卡、确认和商汤排队，不依赖 2-2 的电商批量。2-4 再用 2-3 的镜头图出视频。
- 阶段 2-1：本地跑起画布，打通一条电商路径。上传一张商品图，DeepSeek 看图写出生成卡，你确认，商汤排队出一张主图或场景图，图回到画布上。关掉再打开，图还在，而且只能看到自己的。验收时你自己点这一条，并看到一张真实的图。
- 阶段 2-2：电商批量。两个以上 SKU 共用一套外观设定，只换商品；批量改风格会重新生图；批量改尺寸只做裁切或缩放。验收时你对比两个 SKU，并拿到一组不同尺寸的图。
- 阶段 2-3：短剧出图。写分镜，锁定角色卡，每个镜头出一张图，导出带镜头号的图片包。验收时你看至少 3 个镜头，并给真实样例打分。
- 阶段 2-4：短剧视频。用镜头图交给蚂蚁做图生视频，一次一条。免费额度不够时先报价，你同意才继续。验收时你拿到至少一条真实视频，或者你看到报价后决定先停。
- 阶段 3-0：只写前端适配声明，确认正式界面就是这块画布，不另做 Next.js。
- 阶段 3-1：补画布上还缺的正式体验，包括手机宽度、失败提示、空状态。手册里其余前端子阶段合并进这一段，除非 3-0 发现某段必须单独做。
- 阶段 4：不做。这次不上线。
- 阶段 5：阶段 3 通过后收尾，整理怎么启动、怎么验证，不部署。
- 调整规则：某一段验收时如果要合并、拆开或增减，先改这一节，再记进项目状态的阶段历史，然后才写下一段的开发文档。
