# 第 2-1 阶段技术开发文档｜画布上的一条电商路径

> 配套文档：`docs/PRD/端侧AI-Studio-需求与实现方案.md`、《技术适配声明》。
> 本文档只覆盖 2-1。不实现批量、多 SKU、短剧、视频和上线。

## 一、阶段目标
- 交付范围：本地打开画布，走通一条电商路径。
- 阶段产物：后端接口、一块可平移缩放的画布、自动化测试、重启恢复钩子、产品 README。
- 验收标准：用邀请码进入；上传一张商品图并写下要求；看到生成卡；确认后商汤出一张主图或场景图；图出现在画布上；关掉再打开还在；另一个邀请登录看不到这张图。
- 明确不做：批量改尺寸、改风格、多 SKU、分镜、角色卡、蚂蚁视频、公网部署、整仓 infinite-canvas。
- 本阶段打通的主链路片段：上传商品图 → DeepSeek 看图写出生成卡 → 你确认 → 商汤排队出一张图 → 画布显示并保存。

## 二、技术适配摘要
- 引用《技术适配声明》：纵向切片，画布会留到正式产品。
- 本阶段采用：Python 3.12、FastAPI、Pydantic、pytest、SQLite、本地文件、提交任务后轮询。
- 本阶段启用：用户与作品归属、任务记录、上传文件目录。
- 本阶段偏离：不使用 Next.js，不整仓接入 infinite-canvas。原因见《技术适配声明》第 4 节。
- 开发路径：纵向切片。

## 三、技术栈与模型
- 后端：FastAPI。前端：Vite + React + TypeScript。数据库：SQLite。不引入任务队列软件、向量库、支付宝以外的视频接口。
- 转写：DeepSeek 识图模型。地址和模型名放在 `backend/.env`，代码不写死你的钥匙。
- 出图：商汤日日新生图接口，默认模型 `sensenova-u1.5-lite`，地址 `https://token.sensenova.cn/v1`。用图片编辑接口把商品图和生成卡一起送出。3 把钥匙全局串行，完成或失败后换下一把。
- 不调用蚂蚁。

## 四、环境与配置
- 样例在 `backend/.env.example`。真实值写 `backend/.env`，不进仓库。
- 你要填的是 `DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`、`SENSETIME_API_KEYS`（三把用英文逗号隔开）。邀请码默认 `studio-demo`，可改 `INVITE_CODE`。
- 没有钥匙时，页面仍能打开、登录、上传。生成会停在明确失败，不会假装出图。
- 后端端口 8000。画布开发端口 5173。

## 五、项目结构
- `backend/app/`：接口、数据库、DeepSeek、商汤、生成卡提示词。
- `backend/tests/`：不联网的自动化测试。
- `frontend/`：画布。
- `scripts/restart-check.sh`：重启后数据还在的检查。
- `scripts/smoke.py`：有钥匙时才跑的真实冒烟，自动写记录。
- `data/`：数据库和图片，不进仓库。

## 六、数据、资产与状态
- SQLite 加本地图片目录。第一张表就带 `owner_id`。
- `works`：一块画布，标题。`assets`：上传图和结果图的路径。`jobs`：一次生成。`sessions`：登录。`provider_state`：商汤现在用到第几把钥匙、有没有请求占着。
- 图片只存 `data/files/<owner>/<随机名>`，不使用用户原来的文件名。
- 任务状态：`card_pending` → `card_ready` → `queued` → `running` → `succeeded` 或 `failed`。
- 进程重启时，如果商汤锁还占着，锁释放，没完成的出图任务回到 `queued`。

## 七、API / 工具设计
- `POST /api/v1/auth/login`：`{invite_code}`。成功写入只给本站用的 Cookie。失败 `401`，`{"error":{"code":"bad_invite","message":"邀请码不对"}}`。
- `POST /api/v1/auth/logout`，`GET /api/v1/auth/me`。
- `POST /api/v1/works`：`{title}`，返回 `{id,title}`。用于保存和重启检查。
- `GET /api/v1/works/{id}`：只能读自己的。
- `POST /api/v1/uploads`：图片文件。只收真实的 jpg、png、webp，最大 10 MB。
- `POST /api/v1/jobs`：`{work_id,upload_asset_id,image_type,user_text}`。立刻返回任务号，状态 `card_pending`。后台写生成卡。
- `GET /api/v1/jobs/{id}`：返回状态、生成卡、错误、结果图地址。
- `POST /api/v1/jobs/{id}/confirm`：只有 `card_ready` 可以确认。确认后排队出图，接口不等到出完。
- `GET /api/v1/assets/{id}`：下载自己的图片。
- 错误一律 `{"error":{"code","message"}}`，不返回堆栈。
- 模型不决定要不要出图。只有确认接口会启动商汤。

## 八、Prompt 设计
- 文件 `backend/app/services/prompts/generation_card.txt`。
- 输入：图类型、用户的话、商品图。
- 输出 JSON：`product_appearance`、`scene_and_light`、`style`、`must_not`、`prompt`。`image_kind` 以你在页面上选的为准。
- 解析失败会再请模型说一次。仍失败则任务失败，不扣商汤。

## 九、验收界面或纵向切片
- 这是会留下的纵向切片，不是临时页。
- 桌面和约 390 像素宽都要能登录、上传、看卡、确认、看图。
- 画布可以拖动和滚轮缩放。节点是：商品图、生成卡、结果图。

## 十、测试要求
- mock：邀请码、别人的任务不能看、错误文件、超大文件、生成卡解析、确认后才出图、商汤锁、钥匙轮换、错误格式、作品重启后还在。至少 5 条。
- 真实冒烟：`scripts/smoke.py` 在 `backend/.env` 有两家钥匙时，上传一张小图，走完确认和出图，把一行记录写入 `docs/evidence/阶段2-1/冒烟记录.md`。没有钥匙不写假记录。
- `scripts/restart-check.sh` 用临时目录，写入不调用模型。

## 十一、验收清单
- 打开终端，进入工具包，按 README 启动后打开画布页面。
- 输入邀请码 `studio-demo`，看到一块可以拖动的画布。
- 选「场景图」，上传一张商品图，写「放到木质桌面上，柔和日光」。
- 看到生成卡后点确认。
- 若钥匙已填，画布上出现一张新图，刷新后还在。
- 若钥匙没填，看到的是「还没配置钥匙」，不是一张假图。
- 换一个浏览器或无痕窗口，不登录就看不到这张图。

## 十二、风险与待确认项
- 商汤默认按 2026 年公开的日日新图片接口来接。若你的钥匙不在这个地址，把 `SENSETIME_BASE_URL` 和 `SENSETIME_MODEL` 改成控制台里的值，不要把钥匙发给我。
- DeepSeek 必须是能看图的模型名，否则生成卡会失败。
- 出图可能要一两分钟。3 把钥匙同一时间只用一把。
- 无水印参数按公开文档显式关闭。若以后商汤把无水印改成收费，再告诉你。
- 必须由产品经理决定的问题：无。
